# WhatsApp through WAHA

This fork connects WhatsApp through [WAHA](https://waha.devlike.pro)
(WhatsApp HTTP API) instead of the Meta Cloud API. WAHA drives WhatsApp
Web, so it is **unofficial**: WhatsApp can ban numbers it flags, so keep
volume low and avoid unsolicited bulk messages.

## 1. Run WAHA

Run WAHA next to the app on an internal network. Do not publish its port.

```yaml
# docker-compose.override.yml (example)
services:
  waha:
    image: devlikeapro/waha
    restart: unless-stopped
    environment:
      WAHA_API_KEY: ${WAHA_API_KEY}
    volumes:
      - waha_sessions:/app/.sessions
volumes:
  waha_sessions:
```

## 2. Configure the app

Set these in `.env.local` (see `.env.local.example` for the full text):

| Variable              | Purpose                                                          |
| --------------------- | ---------------------------------------------------------------- |
| `WAHA_BASE_URL`       | WAHA address as seen from the app, e.g. `http://waha:3000`       |
| `WAHA_API_KEY`        | Same key WAHA was started with                                   |
| `WAHA_WEBHOOK_SECRET` | Shared secret on the inbound webhook. Required.                  |
| `WAHA_WEBHOOK_URL`    | App address as seen from WAHA, e.g. `http://app:3000/api/whatsapp/waha/webhook` |
| `WAHA_SESSION_NAME`   | Optional. Set to `default` on WAHA Core (single session).        |

## 3. Link the phone

1. Apply migrations `060_waha_provider.sql` and `061_default_currency_idr.sql`.
2. Sign in as an account admin, open **Settings → WhatsApp** and press
   **Connect WhatsApp**.
3. Scan the QR code from WhatsApp on the phone (Settings → Linked devices).

The app creates the WAHA session, registers the webhook on it with the
shared secret, and shows the status. The session name is generated by
the server from the account; it is never taken from the browser.

## How the pieces are protected

- The session endpoint only ever acts on the caller's own account, so one
  account cannot read another's QR code, start it, or log it out.
- The inbound webhook rejects every request unless `X-Webhook-Secret`
  matches `WAHA_WEBHOOK_SECRET` (compared in constant time).
- `WAHA_BASE_URL` and `WAHA_API_KEY` come from the server environment
  only. The `waha_base_url` column is ignored so an admin cannot redirect
  the API key to another host.

## Known limits

- Message templates are sent as plain text (`name: param1 param2`).
- Interactive buttons and lists are sent as numbered text.
- Delivery/read receipts and reactions are not handled yet.
- Group chats are not filtered out of the inbound webhook.

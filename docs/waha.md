# WhatsApp through WAHA

This fork connects WhatsApp through [WAHA](https://waha.devlike.pro)
(WhatsApp HTTP API) instead of the Meta Cloud API. WAHA drives WhatsApp
Web, so it is **unofficial**: WhatsApp can ban numbers it flags, so keep
volume low and avoid unsolicited bulk messages.

## 1. Run WAHA

Run WAHA next to the app on an internal network. Do not publish its port.

```yaml
# docker-compose.override.yml (example)
services:
  waha:
    image: devlikeapro/waha
    restart: unless-stopped
    environment:
      WAHA_API_KEY: ${WAHA_API_KEY}
    volumes:
      - waha_sessions:/app/.sessions
volumes:
  waha_sessions:
```

## 2. Configure the app

Set these in `.env.local` (see `.env.local.example` for the full text):

| Variable              | Purpose                                                          |
| --------------------- | ---------------------------------------------------------------- |
| `WAHA_BASE_URL`       | WAHA address as seen from the app, e.g. `http://waha:3000`       |
| `WAHA_API_KEY`        | Same key WAHA was started with                                   |
| `WAHA_WEBHOOK_SECRET` | Shared secret on the inbound webhook. Required.                  |
| `WAHA_WEBHOOK_URL`    | App address as seen from WAHA, e.g. `http://app:3000/api/whatsapp/waha/webhook` |
| `WAHA_SESSION_NAME`   | Leave empty. Each account then gets its own session. Setting it forces one fixed name on everyone. |

## 3. Link the phone

1. Apply migrations `060_waha_provider.sql` and `061_default_currency_idr.sql`.
2. Sign in as an account admin, open **Settings → WhatsApp** and press
   **Connect WhatsApp**.
3. Scan the QR code from WhatsApp on the phone (Settings → Linked devices).

The app creates the WAHA session, registers the webhook on it with the
shared secret, and shows the status. The session name is generated by
the server from the account; it is never taken from the browser.

## How the pieces are protected

- The session endpoint only ever acts on the caller's own account, so one
  account cannot read another's QR code, start it, or log it out.
- The inbound webhook rejects every request unless `X-Webhook-Secret`
  matches `WAHA_WEBHOOK_SECRET` (compared in constant time).
- `WAHA_BASE_URL` and `WAHA_API_KEY` come from the server environment
  only. The `waha_base_url` column is ignored so an admin cannot redirect
  the API key to another host.

## Hidden numbers (LID) and delivery ticks

- WhatsApp may hide a sender's number behind an id ending in `@lid`. The
  app asks WAHA for the real number and stores that. If WAHA cannot say,
  the id is kept and replies go to it as an `@lid` chat.
- Before sending to a plain number the app asks WAHA whether it is on
  WhatsApp. A number that is not gives a clear error instead of a message
  stuck at one tick.
- The ticks follow WAHA's `message.ack` receipts: sent, delivered, read,
  or failed. Press **Re-sync webhook** in Settings → WhatsApp once after
  updating so existing sessions start sending receipts.

## Photos, voice notes and documents sent to you

The app downloads each received file from WAHA (using the API key) and
keeps a copy in the `chat-media` storage bucket, so it displays in the inbox
and does not depend on WAHA's private address. Two things must be true on the
WAHA side:

- WAHA has to download media. That is its default; WAHA's own settings
  `WAHA_EVENTS_DOWNLOAD_MEDIA` and `WAHA_EVENTS_DOWNLOAD_MEDIA_MIMETYPES`
  control it, so check they have not been switched off. WAHA Core receives
  and sends media, so no paid edition is needed. If WAHA sends no file, the message still arrives and the inbox shows the
  attachment as unavailable. The app log then says
  `[waha-media] message has media but WAHA sent no file URL`.
- `WAHA_BASE_URL` and `WAHA_API_KEY` must be set on the app: the download
  goes from the app server to WAHA, not from the browser.

## Messages typed on the phone, and chat history

Two things need the session configured a certain way. The app sets both when
it creates or re-syncs a session (Settings → WhatsApp → **Re-sync webhook**),
so an existing session only has to be re-synced once after an upgrade.

- **Webhook event `message.any`.** The plain `message` event only carries
  messages the customer sends. A reply typed in WhatsApp on the phone (or in
  WhatsApp Web) arrives only on `message.any` with `fromMe: true`. The app
  saves it as an agent message in the conversation, so the chat counts as
  answered (dashboard "waiting for a reply" and reply times). Only chats that
  already exist in the CRM are recorded: a reply to a number that never wrote
  in is a personal chat and is ignored. Messages the CRM sent itself also
  come back on this event; they are recognised by their WhatsApp id and not
  saved twice.
- **NOWEB message store.** `config.noweb.store.enabled = true` (with
  `fullSync: false`). WAHA keeps no history without it. The store only holds
  what WAHA receives after it is enabled, plus what WhatsApp syncs when the
  number is linked (about three months with `fullSync: false`, about a year
  with `true`). To get history from before the store was enabled, disconnect
  the number and link it again with the QR code.

In the inbox, **Load history from WhatsApp** (at the top of a conversation,
once every saved message is visible) copies one page (100) of older messages
from WAHA into the conversation. It can be pressed repeatedly to go further
back and is safe to repeat: messages already saved are skipped. Attachments
from history appear as `[Attachment]` because media is not downloaded.

## Message templates

Settings → Template holds reusable messages with blanks (`{{1}}`, `{{2}}`).
They are saved on this server only, with no Meta review, and are usable at
once in broadcasts, the inbox and automations. WAHA sends the text with the
blanks filled in, plus the optional footer. There are no template buttons,
headers or images: write the message as plain text.

## Known limits

- Interactive buttons and lists are sent as numbered text.
- Reactions are not handled yet.
- Group chats, channels and Status updates are ignored by the webhook.
